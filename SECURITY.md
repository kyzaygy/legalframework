# Политика безопасности

## Как сообщить об уязвимости

Пожалуйста, не создавайте публичные issue для уязвимостей.

- Используйте приватную форму GitHub: **Security → Report a vulnerability**
  (Private vulnerability reporting) в этом репозитории.
- Опишите шаги воспроизведения, затронутые URL/компоненты и возможные последствия.

Мы стараемся подтвердить получение в течение 72 часов и исправить
подтверждённые уязвимости в разумный срок в зависимости от серьёзности.

## Область

- Веб-приложение `legalframework.ru` (Next.js, каталог `src/`)
- Импортёр данных (`loader/`)
- Инфраструктура развёртывания (`Dockerfile`, `docker-compose.yml`, `Caddyfile`)

Сайт не имеет пользовательских аккаунтов и не хранит персональные данные;
единственный пользовательский ввод — поисковый запрос и параметры URL.

## Поддерживаемые версии

Поддерживается только последняя версия из ветки `main`, развёрнутая на
продакшене. Исправления безопасности не бэкпортируются.

## Практики

- Зависимости обновляются еженедельно через Dependabot (`.github/dependabot.yml`);
  критичные обновления безопасности (например, патчи Next.js) применяются немедленно.
- CI прогоняет `npm audit --audit-level=high` на каждый push и pull request.
- HTML из внешнего источника (pravo.gov.ru) санитизируется при импорте
  по белому списку тегов (`loader/sanitize.ts`).
- SQL-запросы параметризованы (Prisma), сырой ввод в SQL не попадает.
